2 Existing Backend API Contracts

GET /api/daily-news

Returns the full AI-generated Arabic space story for today's NASA APOD. This is the primary data source for the dashboard.

{
  "success": true,
  "data": {
    "title": "string (Arabic, ≤10 words)",
    "summary": "string (Arabic, 2–3 sentences)",
    "scientific_explanation": "string (Arabic, 3–5 scientific sentences)",
    "key_facts": ["string", "string", "string"],
    "why_it_matters": "string (Arabic, 2–3 sentences)",
    "story": "string (Arabic narrative, 100–150 words)",
    "source_data": {
      "source": "NASA APOD",
      "date": "YYYY-MM-DD",
      "title": "string (original English APOD title)"
    },
    "confidence": "high | medium | low",
    "language": "ar"
  }
}
Important — Image URL: The backend's NASAAPODData model has image_url and hd_image_url fields from the NASA APOD response. However, these fields are NOT currently passed through to the SpaceStory output or source_data. Only source, date, and title are guaranteed in source_data. The frontend must NOT assume an image URL is present.

GET /api/daily-news/status

Returns safe scheduler and bulletin lifecycle metadata. No secrets.

{
  "success": true,

CORS

Backend has allow_origins=["*"] — the frontend can call it from any origin in development. For production, this should be tightened but does not block dashboard development.

Backend runtime notes

  • Backend runs at http://localhost:8000 (uvicorn, from backend/ directory)
  • The /api/daily-news call is not instant — it triggers a live NASA API call + AI model call at request time. Typical latency: 5–30 seconds.
  • The scheduler caches a bulletin to disk in bulletin_store.json — but /api/daily-news does not serve from the store; it always re-generates. The store is only consulted by the scheduler for idempotency.
  • This means the frontend must handle long loading times gracefully.

6 TypeScript Type Definitions (from Backend Contract)

// lib/types.ts

export interface SpaceStory {
  title: string;
  summary: string;
  scientific_explanation: string;
  key_facts: string[];
  why_it_matters: string;
  story: string;
  source_data: {
    source: string;       // Always "NASA APOD"
    date: string;         // "YYYY-MM-DD"
    title: string;        // Original English APOD title
    // image_url?: string; // NOT currently in API — do not assume
  };
  confidence: 'high' | 'medium' | 'low';
  language: string;       // "ar" (may be "en" if Arabic validation failed)
}

export interface DailyNewsResponse {
  success: true;
  data: SpaceStory;
}

export interface ErrorResponse {
  success: false;
  error: {
    code: string;
    message: string;
  };
}

export interface SchedulerInfo {
  enabled: boolean;
  last_run: string | null;
  last_success: string | null;
  apod_date: string | null;
  status: 'success' | 'failed' | 'skipped' | null;
}

export interface LatestBulletin {
  apod_date: string;
  status: 'success' | 'failed';
  generated_at: string;
}

export interface StatusResponse {
  success: true;
  data: {
    scheduler: SchedulerInfo;
    latest_bulletin: LatestBulletin | null;
  };
}

7 Data Flow

page.tsx
  └── SpaceDashboard.tsx
        ├── useDailyNews() hook
        │     ├── fetch("GET /api/daily-news")
        │     ├── states: idle → loading → success | error
        │     └── returns: { story, loading, error }
        │
        ├── useBulletinStatus() hook
        │     ├── fetch("GET /api/daily-news/status")  [parallel, non-blocking]
        │     ├── states: idle → loading → success | error
        │     └── returns: { status, loading, error }
        │
        ├── if loading         → <BulletinSkeleton />
        ├── if error           → <BulletinError error={error} onRetry={refetch} />
        ├── if story is null   → <BulletinEmpty />
        └── if story           →
              ├── <MorningBulletinHero story={story} />
              ├── <ScientificStory story={story} />
              └── <LiveStatus status={status} />

The two fetch calls (/api/daily-news and /api/daily-news/status) are parallel and independent. A failure in the status endpoint must not block or break the main story display.

8 UI States

StateTriggerVisual treatment
LOADING fetch() in-flight Full-section skeleton: animated pulse blocks matching the hero + story layout. No broken content. Arabic loading hint: جاري تحميل النشرة الفضائية…
SUCCESS success: true returned Full dashboard renders with all data from API. No hardcoded fallback content.
ERROR HTTP error or success: false Friendly Arabic error card with icon, message, and a "حاول مجدداً" (Retry) button. Message text comes from the API's error.message field when safe, otherwise a generic Arabic message. Error code never shown to users.
EMPTY Story is null / not ready Deliberate empty state: Arabic text explaining the bulletin is being prepared. No fake content. No countdown timer (that would require backend data we don't have).
DEGRADED Status endpoint fails while story succeeds Story renders normally. Live Status section shows a subtle "unavailable" badge. Never blocks the main content.

12 Accessibility Strategy

  • Semantic HTML: <main>, <section>, <article>, <header> used correctly
  • lang="ar" on Arabic text containers, dir="rtl" on RTL sections
  • aria-label on all icon-only buttons (e.g. retry)
  • aria-live="polite" on loading/error regions so screen readers announce state changes
  • aria-busy="true" on skeleton container during loading
  • Color contrast: minimum 4.5:1 for body text against dark backgrounds — verified against design tokens above
  • Keyboard navigation: all interactive elements reachable by Tab, visible focus ring
  • @media (prefers-reduced-motion: reduce): disable pulse animations and any transitions
  • Mobile tap targets: minimum 44×44px

13 Performance Strategy

  • No polling — /api/daily-news/status is fetched once on mount. Status is a low-value refresh target; no interval timer needed.
  • One request for the main story — /api/daily-news is called once. A retry button exists for user-initiated retries only.
  • No NASA / OpenRouter calls from frontend — all data comes through the backend proxy. Zero API keys in frontend code.
  • Lazy loading — if an image URL is ever added by the backend, use Next.js <Image> with lazy loading.
  • No heavy dependencies — no chart library, no 3D/WebGL, no particle systems. Tailwind is purged at build time.
  • SWR or React Query optional — if added, it provides in-memory caching of the story for the browser session, avoiding duplicate calls on navigation. Not required for MVP.
  • Backend latency — the /api/daily-news call can take 5–30s. The skeleton loading state is critical UX — it must render immediately on page load before the fetch completes.

18 Data Grounding Rules (Implementation Constraints)

Hard rules for implementation — no exceptions.
  • Every field displayed as content MUST come from the backend API response
  • No hardcoded NASA titles, APOD dates, astronomical facts, image URLs
