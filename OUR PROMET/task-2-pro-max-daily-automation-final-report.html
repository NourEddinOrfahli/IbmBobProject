2. Architecture Chosen

APScheduler 3.x AsyncIOScheduler JSON File Store Repository Abstraction

  • Scheduler: APScheduler AsyncIOScheduler with a daily CronTrigger. Pure Python, asyncio-native, no Redis/Celery/Docker. Disabled by default (DAILY_BULLETIN_ENABLED=false).
  • Persistence: bulletin_store.json — a local JSON file behind a thin BulletinStore repository class. Isolates I/O so a future DB swap requires only one file change.
  • Orchestration: New BulletinService layer that checks idempotency, normalises data, calls the unchanged StoryGenerator, and persists results. Both the scheduler and any future API endpoint call this single service.
  • Manual trigger: DailyBulletinScheduler.trigger_now() is available for testing without waiting for the next calendar day.

5. Scheduler Mechanism

DAILY_BULLETIN_ENABLED=true   # enables the job
DAILY_BULLETIN_HOUR=7         # 24-hour time
DAILY_BULLETIN_MINUTE=0
DAILY_BULLETIN_TIMEZONE=UTC   # any IANA timezone (e.g. Asia/Riyadh)
  • At startup, main.py lifespan instantiates DailyBulletinScheduler and calls .start().
  • APScheduler adds a CronTrigger(hour, minute, timezone) job with 1-hour misfire tolerance.
  • Each triggered run calls BulletinService.generate_daily_bulletin().
  • Any exception inside the job is caught — the scheduler stays alive and the next run is unaffected.
  • On shutdown, _scheduler.shutdown(wait=False) is called cleanly.

6. Persistence / Cache Mechanism

A single bulletin_store.json file in the working directory (configurable via BULLETIN_STORE_PATH) stores:

{
  "latest": { "apod_date": "2024-06-15", "status": "success",
              "generated_at": "2024-06-15T07:00:05Z", "story": {...} },
  "records": {
    "2024-06-15": { ... },
    "2024-06-14": { ... }
  }
}
  • The file is loaded once on BulletinStore construction and re-written on every save().
  • Corrupt / missing files are silently ignored — the store starts empty.
  • Swapping to a database requires only reimplementing the 4 public methods of BulletinStore.

7. How Duplicate Daily Generation Is Prevented

  1. At each scheduled run, BulletinService fetches today's NASA APOD first.
  2. The APOD's date field is used as the key — not the server's local date.
  3. BulletinStore.has_record_for(apod_date) returns True only if a successful bulletin already exists for that exact date.
  4. If True, the pipeline is skipped and None is returned (logged as "skipped").
  5. A failed record does NOT block a retry — only status == "success" skips.
  6. The manual force=True flag bypasses the check entirely for admin/test use.

8. NASA Data Flow Into the AI Pipeline

scheduler._run_job()
  └── BulletinService.generate_daily_bulletin()
        ├── NASAClient.get_apod(None)          ← NASA date is authoritative
        ├── NASAClient.get_donki_cme()          ← non-fatal
        ├── _normalise_apod(apod)               ← truncate, strip whitespace
        ├── _filter_donki_events(events)         ← remove events without begin_time, cap at 5
        └── StoryGenerator.generate_daily_story(apod_date)
              ├── build_prompt_for_apod(apod, donki)
              ├── AIProvider.generate_structured_response(...)
              ├── _ensure_source_data(raw, apod) ← NASA provenance always wins
              └── SpaceStory(**raw)              ← Pydantic validation

The existing StoryGenerator is called unchanged. _ensure_source_data always overwrites source, date, and title from the verified NASA object — no hallucination of provenance is possible.

13. Remaining Limitations

  • The JSON store is a flat file — no concurrent write protection. For a multi-worker (Gunicorn) deployment a database would be required.
  • The scheduler runs inside the FastAPI process. If the process is restarted between the configured time and the check, the job may misfire (APScheduler's misfire_grace_time=3600 mitigates this for up to 1 hour).
  • GET /api/daily-news still re-generates on every call — it does not read from the store. This is intentional to preserve backward compatibility. A future optimisation could serve the stored bulletin for the current APOD date if present.
  • Timezone relies on the system having the tzdata package (installed automatically with apscheduler).
